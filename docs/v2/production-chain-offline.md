# Offline draft and structural review in the synthetic chain

This engineering path uses explicitly fictional sources and owned state. It
does not perform research, contact a provider, issue medical advice or call a
model. Existing model/service settings are unchanged.

`test_chain_offline_draft.py` actually initializes a fresh `macos_enforced`
deployment and calls production CLI tools. It registers a fictional public
source, caller-attested selected-text access and a finding with a literal
excerpt/locator. A deterministic source-supported draft then passes backend
structural reference resolution. Replacing its finding ID with bibliographic
metadata fails that check.

The source record remains caller/model-attested, never backend-fetched. No
semantic checks are invented: source alignment stays `not_checked`, release
state stays `needs_revision` and medical validation stays `not_provided`.
Passing this test proves actual CLI transport and structural binding, not
automatic skill routing, model quality, source entailment or guideline
currentness. The fixed 24-fixture model protocol remains a separate gate with
zero executed outputs.

The companion installed private chain saves an actual synthetic case selection
after explicitly simulated decisions. Selected case facts, source pixels,
revision IDs and subject identity remain offline. They are never arguments to
the public research/review surface. A local synthesis artifact may link the
selection with this public draft and its structural receipt, but that linkage
does not add a private answer resolver to the backend.

The current public reviewer rejects private case facts. Persisted private
answer resolution and independent substantive review remain unfinished A16
work. The bounded chain therefore records the exact point reached rather than
labeling its combined personal draft reviewed or ready. Synthetic test
conversation provenance is openly simulated; no actual human, patient or
clinician decision follows from it.
